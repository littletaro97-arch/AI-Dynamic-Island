# 悬停设置与 WorkBuddy 积分权限诊断

开始时运行的是本地 `061070d` 验收版。保存设置中 EnableHoverExpansion=false、EnableReverseHover=false，普通悬停不会展开；不是把两个模式都关闭视为非法配置。本机按用户需求备份后只恢复悬停开关，延时及其他设置保留。

已安装 WorkBuddy 5.7.6，积分 discovery 文件存在，包含原有 endpoint、ticket 两项；未打印凭据。生产读取链路及独立只读连接均在 NamedPipeClientStream.Connect 阶段得到 UnauthorizedAccessException，尚未进入协议握手或积分接口调用。可查询的 WorkBuddy 进程令牌显示 elevated，岛及诊断端为普通权限；部分进程的令牌读取也被拒绝。证据指向当前连接权限差异，不能据此确认所有升级后的 API 字段不变，也不能把尚未读取的响应描述成解析成功。

用户最初选择不重启，随后明确说明任务已执行完毕并授权操作。普通权限关闭请求被 Windows 拒绝后，使用一次 UAC 的临时辅助脚本关闭已核验路径的旧 WorkBuddy 进程树，再从普通权限启动同一 EXE。没有提高灵动岛权限、修改管道访问控制、改登录或认证配置。重启后生产读取链路返回 Available=true、Error=null，积分有效；证明本机 5.7.6 的现有握手和积分字段仍可使用。当前失败与权限差异有关，不需要变更 API 路径或伪造客户端身份。

本轮补充 connect 阶段诊断，显示“积分不可用（连接权限）”，发现文件访问被拒绝时显示不同的文件权限提示。折叠摘要与展开积分行复用同一格式化逻辑；有效积分优先显示数值。未知接口错误保留通用提示，不伪装成确定的权限故障。

没有增加轮询频率或重试定时器，沿用原 60 秒积分缓存。权限或宿主状态改变后，可通过“重置并重新检测”清除缓存并立即重试。本次切换新验收版也会从空缓存读取，真实鼠标与页面显示由用户验收。

验证：DisplayNotificationChecks 259 项、ActivityChecks 640 项、PerformanceChecks 49 项通过。新增检查区分连接/文件权限与未知 API 错误，验证有效积分覆盖过期错误标签，以及启用/关闭普通悬停时的计时器行为。真实鼠标展开仍由用户验收。本轮仅本地提交和启动验收版，不发布或打包。
