# 并行完成提醒、Harness 检测与资源优化

日期：2026-10-02。基线提交：`6d22919`，本地分支：`codex/parallel-completion-harness-performance`。版本号仍为 0.7.2；本轮只有源码、测试及 Git 提交，没有正式包、Release、远端推送或安装程序替换。

## 行为变化

完成事件与应用整体忙碌状态分开判断。Codex 从各会话 final_answer 读取完成事件，WorkBuddy 从各会话已完成的助手消息读取，YOYO 使用现有 SDK 的历史消息及 execution.get_view 的 completed 状态确认。某个会话结束、其它会话继续时，顶部继续显示执行中，完成提醒仍展开灵动岛并显示具体结果。

事件按来源和 ID 去重，按时间排队。首次检测建立基线，不补播历史任务；只接收监控启动后、最近 30 分钟内的事件。待决策提醒优先，期间收到的完成事件保留到决策结束。最多保存 64 条待展示事件，旧队列满时淘汰最早事件。

轮询窗口有边界：Codex 16 个完成候选/32 个活动候选，WorkBuddy 24 个会话，YOYO 最近 8 个会话，每会话读取有限尾部记录。超出候选范围、极短时间产生超过尾部窗口的事件，不保证全部捕获；这不是系统级无损事件订阅。

未运行状态旁新增隐藏图标。点击后隐藏该来源的标题、展开行、积分/额度、状态点及菜单状态，停止向它显示提醒。该应用的开关设置仍保留，且进程检测继续；重新运行时恢复，使用渐隐、渐显及高度过渡。隐藏列表保存到本机配置，灵动岛重启后仍生效，来源重新运行时自动清除；该临时状态不进入方案快照。

另修复 WorkBuddy 缓存将超过 30 秒的长工具调用误判为空闲的问题。尚未结束的工具调用在两小时有效窗口内保留忙碌状态，待决策状态保留；新用户消息会开启新的忙碌判定。

## DeepSeek Harness 实验支持

参考[官方项目](https://github.com/deepseek-ai/deepseek-harness)，并检查本机官方桌面程序 `@deepseek-ai/dsh-desktop` 0.2.0-rc.2 中实际安装的会话、代理循环及用户审批模块。

新增第四来源、组件开关、安装路径选择、拖动排序、状态点和打开应用入口。检测采用只读的 `.dsh/sessions/**/session.v4.jsonl.zstd`，使用该安装目录自带的 Node 24 Zstd 支持解压，不读取凭据、不操作会话、不添加 Harness 插件或修改其配置。

| 记录 | 岛中状态 |
| --- | --- |
| turn/start 尚未结束 | 执行中 |
| turn/end，reason.kind=completed | 已完成、完成事件 |
| turn/end，错误等非正常结束 | 任务异常 |
| approval/asked 尚未 decided，或 ask_user_question 尚未回答 | 待确认 |
| turn/end，aborted 等取消 | 已停止，不发成功提醒 |
| 未知格式、读取失败、长时间未闭合 | 状态不可用/待核实 |

支持超时后继续等待的用户问题与后续 user-question-reply。未结束日志超过两小时不会直接作为正在执行的证据。过去完成/错误状态超过 30 分钟回到空闲展示。旧格式只有空会话头时可确认没有事件；有实际内容的旧日志或未来格式会拒绝解析，避免假报状态。

一次最多读取 24 个会话，每文件压缩上限 8 MiB、解压上限 32 MiB。文件签名未变化时复用结果，忙碌/未知状态每 30 秒重新检查过期性。内置 Node 或脚本缺失时显示不可用。

## 资源开销与证据

正在运行的安装版一次 20 秒只读采样记录：16 个逻辑处理器，平均 CPU 约 0.63%，工作集约 677.5 MiB，私有内存约 557.9 MiB。这个短样本没有复现 3–4% 的峰值，不能推断不存在峰值或长期问题。

已实现：

- Codex 一次刷新共享候选枚举；用固定容量优先队列选择新文件，避免先排序全部历史会话。
- JSONL 尾部先按字节筛选生命周期/完成标记，再解码；不再为无关工具输出创建大批字符串。活跃度仍依据文件写入时间，不把长工具调用当成闲置。
- YOYO 未运行时停止启动状态桥接；Codex、WorkBuddy 未运行时停止扫描历史会话。
- 相同的普通摘要不重复重建文本；额度滚动由每帧 Rendering 回调改为 30 Hz 定时推进，展开或隐藏时停止。
- Harness 文件签名未变化时避免每轮启动解析进程。

约 0.9 MiB 模拟尾部的单轮托管分配：原不筛选路径 1,828,944 字节，筛选路径 720 字节。该数据只代表这项读取的分配，**不是整个应用工作集或 CPU 的下降比例**。当前安装版未替换，尚没有新版应用长时间运行的前后对照。

## 验证边界

常规编译通过；ActivityChecks、SettingsChecks、SettingsCardChecks、QuotaChecks 通过，Harness 状态解析用例与 YOYO 桥接脚本语法检查通过。覆盖并行完成、去重、决策期间排队、忙碌标题、隐藏/恢复/保存状态、四来源布局、长工具调用缓存和无关日志分配。

新版检测器只读访问真实 Harness 成功：running=True、available=True、state=idle。本机已发现的日志只有会话头；执行中、成功、异常、用户决策四类真实任务，以及 YOYO SDK 并行结果，仍需人工任务验收。控件检查不代表已验证真实桌面动画。

后续验收：每个应用启动两个任务并分别完成；让 Harness 运行、成功、报错、请求审批/问题；点击隐藏后重启岛、再重启来源；检查全屏与仅活动显示；采样新版稳定运行至少 10 分钟并与相同负载的安装版比较 CPU、工作集及托管堆。当前运行的安装版没有被关闭或替换。

回滚使用本轮提交的 `git revert`；新增配置字段有默认值，现有安装包和发布标签保留。
