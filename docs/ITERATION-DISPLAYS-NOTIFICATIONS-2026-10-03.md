# 副屏定位、系统通知与 Codex 询问提醒（本地迭代）

基线：GitHub v0.7.3，本轮仅本地分支 `codex/display-notifications-iteration`；版本号、公开更新清单和 Release 均不改动。

## 已实现

- 位置页默认显示主屏，增加“前往副屏 / 返回主屏”，超过两屏时可逐屏切换。中央标注主副屏及横竖方向，按 Windows 当前显示边界识别方向，不按物理摆放猜测。
- 主屏与副屏分别保存六个标准位置；自定义微调也按各屏边界保存。副屏采用 Windows 提供的监视器接口标识，断开时回到主屏的已保存位置，保留副屏偏好及配置，接回后恢复。显示变化通知做 280 ms 合并，切换与预览带过渡动画及连续反向切换保护。
- 程序安装路径列仍从原位置开始，DeepSeek Harness 名称在固定名称列内显示省略号，完整名称可悬停查看。
- 提醒分类新增“同步系统通知”组合卡片，默认关闭；开启后读取 Windows 通知中心的 Toast 文本，展开岛显示标题和正文，顶部原额度区域显示通知来源。显示时长单独设置为 3–60 秒，默认 10 秒。权限可通过“通知授权”申请；撤销权限后停止监听。
- 启用监听先建立历史基线，新增或内容改变的通知才显示，保留系统原通知，不删除通知中心记录。通知内容不写入配置、日志或仓库。消息排队显示，待决策提醒优先；突发队列最多保留最新 20 条，原系统通知仍然保留。
- 新增“Codex 待回答”开关。读取明确的 `request_user_input` / `request_user_input_async` 调用与对应回答，进入“待回答”并展开。异步工具的 `accepted=true` 只是投递成功，不能当成用户已回答；匹配回答后解除状态。引用文档中的工具名称不会触发提醒。

## 系统通知能力与限制

使用 Windows 官方 `UserNotificationListener`，需要用户允许通知读取。项目改用 Windows SDK 的 .NET 投影，仍为 .NET 8 WPF；运行最低平台标注为 Windows 10 build 14393，实际验证机器为 Windows 11。未迁移 Inno 安装器或便携分发方式。

本机只读探测：权限 `Allowed`，能读取 35 条通知；`NotificationChanged` 订阅返回 `0x80070490`。生产服务自动降级为仅启用时每 2 秒检查一次；事件订阅可用的机器则使用事件，60 秒校准一次。关闭后停止定时器和订阅。约 2 秒的检测间隔、显示排队会造成延迟；两次检查之间已经消失的通知不保证捕获。

“系统通知”指 Windows 通知中心的 Toast。应用自己绘制的弹窗、托盘气泡或没有提交到通知中心的提醒不在此 API 覆盖内；图片和交互按钮仍需在原应用或通知中心查看。

微软说明：[通知监听接口](https://learn.microsoft.com/en-us/windows/apps/develop/notifications/app-notifications/notification-listener)。未打包桌面应用事件订阅异常的记录：[WindowsAppSDK issue 6172](https://github.com/microsoft/WindowsAppSDK/issues/6172)。本机使用读取轮询的决定来自实际探测，不把 issue 中的现象当成本机证据。

## 额度重复提醒排查（未修复）

- 当前用户配置是提前 40 分钟，而非默认 15 分钟。
- 去重键为“窗口类型 + 重置时间完整字符串”，只有进程内两个字段保存最近键；不同剩余额度百分比本身不会再次触发。
- 保存的应用状态为五小时窗口 `2026-10-03T13:00:14+00:00`；本轮只读接口返回 Unix `1791032413`，即 `2026-10-03T13:00:13+00:00`，相差 1 秒。周窗口的两次只读接口值也从 `1791599078` 变为 `1791599077`。
- 只要落在 40 分钟窗口内，时间的细微变化就会产生新键；此外重启或“重置并重新检测”会清空去重字段。五小时和周窗口分别提醒，也可能产生两个合理提示。
- 因此发现了可解释重复提醒的具体路径，但没有 40、32、31 分钟三个触发时刻的完整历史，不能声称逐次复现了用户当时的弹岛。现有 `UpdateCodexResetReminder` 方法保持原样，没有改用模糊时间桶、持久化去重或修改提前分钟设置。
- 推荐后续方案：按实际额度周期识别已提醒事件，对秒级抖动容忍，同时保留真正新周期、主动重置额度以及五小时/周窗口的区分；修复方案需单独实施和验证。
