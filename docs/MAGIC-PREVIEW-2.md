# Magic 适配本地验收 0.8.0-preview.2

本次只处理 Magic 适配交互及进出切换，不创建正式发布包，不修改公开更新清单，不推送。

## 修改

- WPF 宿主下的 WinForms 弹出菜单不能依赖其消息过滤器完成外部点击关闭。新增仅在菜单可见时安装的鼠标观察钩子；点击菜单外关闭菜单，原点击继续传递，关闭或退出适配时释放钩子。同时去掉菜单中重复的当前助手入口。
- 系统通知保留 AppUserModelId 和最新消息身份，点击后复用 NotificationAppLauncher。失败提示复用现有文本，只替换通知内容，来源及合并计数保留；慢激活期间暂停阅读计时，结果返回后至少保留三秒。新消息到达时，旧激活结果不会覆盖或删除新消息。
- UIA 布局读取暂时失败时，对此前有效且实际仍可见的顶部栏保留布局最多 250 ms 并请求重读；UIA 短暂 offscreen 与真实窗口曝光冲突时采用曝光判断。真实智能隐藏、全屏遮挡继续立即隐藏，不使用这段宽限。托盘闪烁是否全部消除仍需用户实屏验证，不能用模拟样本代替。
- 设置开关和导航图标从本机 MagicVisuals.exe 提取官方图标，不打包截图或重绘标志。读取在后台，冻结图像后显式回到 WPF Dispatcher。

## 挂起现场

用户报告进入 Magic 时卡死，抓取现场确认进程未退出但无响应。实时线程栈显示主 UI 线程停在 StatusForm.Initialize → Attach → Native.Windows 的枚举回调；SystemEvents 线程同步等待 WPF Dispatcher。结合回调中同步 GetWindowText，存在查询本进程隐藏窗口标题与系统事件回调相互等待的路径。

修正：主程序缓存有效 Magic 顶部栏句柄，首次查找跳过本进程窗口；适配直接接收已识别句柄，Attach 不再遍历桌面窗口标题。挂起现场转储和线程栈保留在本地忽略的 evidence/integration/hang-20261012 目录，不提交真实转储、配置及截图。因 UI 已阻塞，在保留现场及配置后结束旧验收进程并启动新版。

新增 magic-lifecycle.log 和 magic-layout.log，仅记录切换步骤、显隐和布局错误，不记录消息内容；日志写入后台，大小有界。原 crash.log 本次没有该挂起的新异常，因为这是线程阻塞。

## 验证边界

- 编译零警告、零错误。
- MagicChecks 75 项通过：来源合并、消息激活身份与旧结果隔离、慢激活阅读时间、真实隐藏无宽限、瞬态布局有界恢复。
- MagicInteractionChecks 10 项通过：实际菜单创建和观察钩子释放；用注入的钩子数据模拟菜单外点击；通知点击路由及异步失败反馈；官方图标提取；自有标题查询陷阱与重复适配创建/关闭。
- SettingsChecks 通过，包括无安装/关闭时不加载适配、普通设置恢复、实际 UIA 工作线程释放。异步图标回调跨线程问题在测试中发现并修正。
- DisplayNotificationChecks 普通模式回归通过，既有失败提示文本保持一致。
- 新实例响应正常，进入日志达到 enter ready，保持打开。官方图标在实际桌面截图中可见。
- 上述注入的点击、模拟的布局瞬态和重复创建关闭，不等于用户在 Magic 托盘和应用通知上的实屏验收。仍需验证真实通知激活、托盘展开收起及进出 Magic。
