# 通知点击优先恢复现有应用（2026-10-03）

## 原因与通用修复

旧实现直接打开 `shell:AppsFolder` 的注册启动入口。QQ 藏在托盘时，所有进程的 `MainWindowHandle` 都为 0，但实际仍有隐藏的顶层主窗口；再次执行启动入口可能生成新的登录窗口。微信的注册通知身份还可能是完整 EXE 路径，旧身份校验会拒绝这种合法形式。

现在先通过 Windows AppsFolder 核对通知的注册身份，读取注册的目标程序路径；按窗口 AppUserModelID 和完整进程路径识别实例。包括隐藏的顶层窗口，排除托盘宿主、工具窗口、有所有者的窗口、无标题窗口和小型辅助窗口。优先精确身份、已显示窗口、较早运行的进程及该进程的大型窗口，恢复并检查前台窗口是否确实匹配。

识别到现有进程但无法恢复有效窗口时，提示从系统托盘打开，不再执行启动入口。进程访问受限时也保守处理。只有没有识别到现有实例时才使用注册的 Shell 入口启动。通知标题、正文、链接和未经注册核对的文件路径不会成为启动命令。

这是一套通用策略，没有添加 QQ/微信专用窗口规则。无法保证所有应用都暴露可恢复的顶层窗口，也不能从普通系统通知获得聊天对象的原生跳转参数；当前目标是恢复来源应用界面，多账户/多个有效窗口仍采用上述确定性优先级。

## 性能

应用注册查询、进程查询和窗口枚举只在用户点击时执行，放在临时 STA 后台线程。没有增加轮询、常驻工作线程、定时器或窗口缓存。前台确认最多等待 150ms，退出后释放 COM 引用。未进行新的 CPU/内存前后基准测试，不能据此声称资源占用下降。

## 验证与边界

- Release 编译通过，无警告或错误。
- DisplayNotificationChecks 检查通过：隐藏主窗口选择、新登录进程避让、辅助窗口过滤、精确身份优先、路径身份校验、未注册程序拒绝、通知失败反馈和原有通知/显示器回归。
- 本机 opt-in native 检查成功解析 QQ、微信注册程序入口。
- 本机 opt-in live activation 检查：QQ 与微信均返回 `Opened`（前台句柄确认通过），两次恢复均未新增对应进程。
- 端到端的手机消息→岛通知→用户点击体验仍需用户验收；自动检查没有代替视觉或聊天对象跳转验收。

检查命令：`dotnet run --project tests/DisplayNotificationChecks -c Release`。本机原生通知检查另设 `ISLAND_NATIVE_NOTIFICATION_CHECK=1`；`ISLAND_ACTIVATION_SMOKE=1` 会实际恢复本机已运行的 QQ、微信窗口，仅供主动桌面验收使用，不应在常规无人值守检查中启用。
