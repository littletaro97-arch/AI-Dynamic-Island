# 后台持久化与主题复用优化

基线为 aabdc62，保留 YOYO 跨日签到修复。本轮不改变版本号、不生成应用构建或发布包、不替换运行版本、不推送。

## 现场基线

当前安装版 v0.7.5（PID 仅用于当次只读采样），16 个逻辑处理器，15.09 秒采样：归一化平均 CPU 0.278%；工作集 689.6–693.0 MiB，私有提交 532.5–535.9 MiB。用户界面状态未受控，该数据只作为现场快照，不能与独立测试或后续不同负载直接比较。短采样不能证明内存泄漏，也不能证明优化后的整应用 CPU/内存下降。

## 已实施

- 状态快照仍按原频率、字段和更新时间生成。界面线程只捕获不可变值，序列化、目录操作与写盘全部在后台。先写临时文件再替换，避免诊断读取撞上半份 JSON。关闭窗口时拒绝新快照、清除等待项；已开始的文件操作可以结束，不访问界面。
- 新的通用队列同时复用于异步配置保存：每个队列最多一个工作任务、一个待写快照，磁盘变慢时覆盖旧等待项，不堆积 Task。配置保留原版本锁，并在合并时优先更高版本，避免迟到的旧提交吞掉新设置。
- 高频 ApplySettings 与 SavePosition 不再同步写配置，仍在界面线程序列化稳定配置快照；正常关闭时，仅对发起过异步设置保存的窗口补做一次同步最终保存，避免进程退出丢失最后操作。此退出保底可能等待正在写盘的配置任务，不属于拖动/滚动的正常交互路径。原同步保存 API 仍保留。
- 灵动岛与设置窗口的有效浅深色未变化时，不再重建笔刷、重设动态资源和标题栏颜色。实际主题切换仍使用原逻辑。没有降低分辨率或帧率，也没有修改检测、动画、通知、额度和签到频率。

## 验证与局限

独立 PersistenceChecks 14 项检查覆盖慢写盘、10000 次突发更新仅保留最后等待项、单工作任务、空闲后重启、失败恢复、关闭清理、并发生产者、配置版本顺序、合法 JSON 和临时文件替换。此前 YoyoCheckinChecks 15 项全部通过。测试仅编译这些独立服务，未构建 WPF 应用；没有读写真实配置或状态、发送签到请求。

虚构约 4 KiB 快照、1000 次紧密连续调用的最终一次观测：原同步序列化写盘调用线程合计 492.45 ms，后台提交合计 0.103 ms；P95 0.7086 ms / 0.0001 ms；后台实际写盘 2 次。结果对磁盘与系统负载敏感，属于合并写入和移出调用线程的局部证据，不表示总工作消失，也不是整应用 CPU 降幅或显示器帧率。日常低频更新可能仍每次都写入，收益集中在避免界面等待与连续设置修改时的合并。

新增驻留上限为每个队列一个正在处理快照与一个等待快照，不缓存历史状态。当前较高的安装版内存读数仍需相同版本、缩放、展开/设置负载的长时观察；本轮不以强制 GC、工作集修剪或画质牺牲制造下降读数。WPF 集成编译、真实设置滑条、主题切换与退出再启动验收待后续用户授权构建验收版。
