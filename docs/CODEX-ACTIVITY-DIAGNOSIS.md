# Codex 执行时状态点误绿：排查记录

用户报告为合入主程序前的独立实验，截图时间 2026-10-12 16:29:40。只读核对指定聊天：对应回合 16:11:15 开始，16:52:06 结束；截图时确实正在执行。

旧链路：状态点使用主程序 status.json 的 busy 字段；主程序 0.7.7 的执行状态主要读取 JSONL 生命周期。独立实验另读分页数据库时只使用提问及完成信号，未把执行状态覆盖到状态点。

指定聊天为 paginated 模式。截图时最后一个 task_started 距文件末尾 1,296,905 字节，超过 1 MiB 生命周期读取窗口；文件 mtime 仍为 14:29:03，不能满足十分钟内扩大读取窗口的条件。冷读取或丢失该会话缓存时，可以得到空生命周期状态而误绿。已用不含真实消息的隔离长会话复现。由于缺少当时缓存及候选列表快照，不声称还原了全部三次现场的缓存路径。

当前合入版 264ef06 已在共享 CodexStatusService 中补充分页 inProgress 回合状态，完成/中断后恢复空闲；不存在仅换颜色的掩盖措施。实际新版快照观察到 busy=true，同时旧 JSONL activeSessions=0，证明新状态源正在发挥作用。activeSessions 字段仍是旧 JSONL 诊断计数，不能单独当作整体忙碌判据。

新增 CodexActivitySourceChecks 共六项：旧长尾漏标记复现、分页补充忙碌、Codex 退出清除缓存忙碌、完成后空闲且排除 guardian、再次执行恢复忙碌、中断后恢复空闲。全部通过；数据库写入仅发生于生成的测试目录，真实 Codex 数据库保持只读。

本轮没有改运行代码或重启验收程序，仅补充回归检查和排查记录。其他两次没有现场数据，仍需后续观察是否同因或存在其他路径。
