## 判断与范围

先做同一台 Windows 电脑上的监控客户端联动。由监控项目产生检测结果、异常和汇报事件，岛负责通知展示、聚合、去重和用户控制。岛不直接读取监控 SQLite 数据库，也不根据网页文字推断事件；这会把采集规则和数据库升级耦合到两个项目。

推荐使用当前 Windows 用户可访问的命名管道，监控程序内接入一个轻量发送适配器，岛提供接收端。接口主动鉴权、限制消息大小和来源，而不是启动可被局域网访问的开放 HTTP 服务。Windows/Python 发送端需验证真实安装包内的管道依赖和运行能力后再冻结实现细节。

Android → Windows 是第二阶段：需要独立的用户配对、HTTPS 和可撤销设备权限。不能把本机管道直接暴露到网络，也不能把现有历史数据同步接口直接当作通知通道。Android 原生通知应继续可用，不依赖电脑在线。GitHub 用于版本与源码管理，不作为实时消息中转。

## “联动”板块

左侧目录和右侧内容顺序：位置 → 外观 → 组件 → 行为 → 提醒 → 方案 → **联动** → 更新。本轮不添加该菜单或占位开关，待用户批准实现时再接入。

板块包含：

1. 联动总开关，默认关闭。
2. Bilibili Monitor 来源卡片：未安装/版本不支持/未连接/已连接、最近接收时间、测试通知。
3. 三类独立订阅：检测结果通知、异常增长提醒、定时汇报；各自可关闭。
4. 通知方式：岛内、系统通知、两者。首轮默认两者，验证可靠后再开放仅岛内模式及系统回退。
5. 静默时段、通知展示时长、点击打开监控详情。与现有全屏、仅活动显示和自动隐藏策略保持一致，用户明确开启的通知不能被“状态未变化”规则永久吞掉。

卡片、滑条、展开、开关、编辑和导航均沿用现有主题与过渡要求。方案可保存订阅与展示偏好；配对凭据、连接状态和设备身份属于本机，不写入方案。

## 事件与展示

协议首版至少包含 `schemaVersion`、`sourceId`、`eventId`、`type`、`occurredAt`（UTC）、`expiresAt`、`severity`、`title`、`summary`、`bvid`、可选统计值与采样窗口、受限详情动作。消息上限建议 16 KiB，文本限制长度；不传递原始数据库、Cookie、Token、评论正文或任意脚本/命令。

事件类型：`collection.completed`、`collection.failed`、`growth.alert`、`report.summary`。发送重试复用 eventId，接收端去重并检查协议、来源、有效期和大小。批量检测合并为一条摘要；去重身份、来源和有限的诊断记录本地持久化。

岛中展示来源图标、简短结论和变化量，展开后显示视频标题与详情入口。AI 最近回复保留在原来源，不被 B站汇报覆盖。采用统一通知队列：待用户确认的 AI 提醒优先，异常增长其次，普通汇报最后；频繁低优先级事件合并，过期事件不补播。

“接收成功”和“已经展示”是不同状态，协议应分别确认。仅岛内模式不能因为管道写入成功就立即放弃系统回退；未确认展示、岛退出或连接失效时由发送端按同一 eventId 处理回退。主动关闭某类订阅产生明确的抑制结果，不误判成断线而重复通知。

详情链接只允许已注册的监控端点和确定的视频标识；不从事件执行任意路径或 shell。双方关闭联动不影响正常抓取、存储、报表与原生通知。

## 异常增长和定时汇报

异常规则在 bilibili-monitor 中实现，岛只消费结论。第一版采用“绝对增量门槛 + 相对增长/增长速率门槛 + 最小采样间隔”，按视频和指标冷却、去重。新视频只有一个快照时不判异常；失败采集、缺字段、计数回落、历史导入和跨设备重复快照不得当作异常增长。阈值需根据真实采样间隔与用户需求确认，不在规划阶段假设一个通用百分比。

汇报周期独立于采集周期，由监控端调度，输出本周期正常采集对象、失败、指标变化和主要增长视频。没有有效新样本时显示“暂无有效变化/存在缺口”，不生成虚构排名或“零增长”。岛不能同时再维护同一汇报定时器，以免两边重复发送。

## 实施顺序与验收

1. 确认监控客户端可回滚基线；冻结事件契约和模拟事件，先完成连接、检测摘要及断线回退。
2. 监控端加入异常规则和定时汇报；再接入岛中展示与分类设置。
3. 做 Windows 双安装包联测与升级兼容，再评估 Android 配对通道。

必须验收：双方各自关闭/重启、未安装或旧版本、停用订阅、重复消息、消息过期、异常/不完整数据、超长文本、断线回退、真实窗口点击详情、全屏与多任务提醒抢占、双方升级后协议兼容、配置回滚。不得用控件编译通过替代双进程通知实测。

可选后续：多个项目来源、通知历史、按视频订阅、Android 事件转发。首轮不引入云中转、通用插件市场、跨设备数据库共享或复杂消息中间件。
